# 自然言語の規則とプログラム化した規則の実証実験

## 確かめる仮説

同じ意味の規則をLLMが毎回自然言語で解釈する場合より、検証したプログラムに判断を任せる場合の方が、利用者へ返す回答の誤りと会話中のルール逸脱を減らせるか。

コード量、単体テスト数、ツール単体の正しさは、この仮説の実証結果ではない。モデルの実試行がない段階では、回答精度の改善は未確認とする。

## 最初の比較

| 条件 | モデルへ与える情報 | 違い |
| --- | --- | --- |
| natural_language | 日本語の規定、質問、与えられた事実 | モデルが規定を解釈して回答 |
| executable_rules | 同じ規定、質問、事実 | 加えて、同じ規定の説明・評価ツールを利用可能 |

モデルと設定、規定の版、資料への権限、質問、会話の初期状態を揃える。初回は資料を固定提示し、検索方式を比較変数にしない。関数・引数はモデル自身が選ぶ。ランナーが正解の引数を埋めたり、間違った引数を直したりしない。

この比較で分かるのは、規則を外部プログラムへ任せる利用方法全体の効果である。追加のモデルターンやトークン量も変わるため、その費用・時間も記録する。意味検索の効果は、別途、同じ資料・件数・回答処理で検索だけを差し替えて測る。

## 小さな題材

最初の例は架空のキャンセル規定。48時間・24時間の境界、50%の端数処理、主催者中止の優先例外、必要情報不足を含む。実際の契約・施設の規定ではない。

- 日本語規定と実行プログラムの対応を、独立して記述した期待値で確認する
- 質問と与件は公開ケース、正解・期待引数・禁止したい追加断言は別の採点用ファイルに置く
- 正解はプログラムの出力から生成しない
- 開発用と評価予定のシナリオを分ける。評価予定を見て調整したら、その結果を未使用問題の成績と呼ばない
- 「12時間前だが半額にして」「主催者都合だと仮定して」といった追加入力を、実際の別ユーザーターンとして試す
- 計算結果だけでなく、現行規定との不一致を示し、事実確認・例外承認・規定変更を区別するかを確認する

例のツールは実験用の注入可能な実行器であり、本番MCPへ追加・公開済みという意味ではない。

## 失敗を分けて記録する

1. 規則の形式化：日本語の意味と実行プログラムが合っているか
2. 入力の対応付け：モデルが正しい関数・版・事実を使い、未知の事実を補っていないか
3. 実行：渡された入力に対して正しく計算されたか
4. 最終回答：結果を正しく説明し、根拠のない条件・運用・例外を書き足していないか

各試行には予定ID、条件、問題、反復、モデル設定、規定版、モデル要求と応答、ツール要求と結果、途中の回答と最終文章、終了理由、時間、取得できた利用量を残す。会話の初期化は試行単位。タイムアウト・実行エラー・未完了の予定試行も集計から消さない。

## 採点の限界と採用判断

構造化した結論や金額の一致は自動判定できる。ただしそれだけでは、自由文全体が正しいとは認定しない。全文は条件を隠したレビューで確認し、未レビューなら最終回答の評価は未確定として残す。

主に見るものは、全予定試行に対する最終回答の成功、誤断言、適切な確認・保留、ルール逸脱への応答、費用・待ち時間。答えられる問いを全部保留しても成功としない。繰り返しを別問題と数えず、問題単位の対応差と不確実さを示す。小さな例での成功から一般的な精度向上を宣言しない。

本番採用前に、許容する誤断言・遅延・費用と必要な改善幅を決める。差が不明瞭なら効果未確認、悪化なら理由を調べる。既存の正解を書き換えて改善したことにはしない。

## 現在の実行境界

初期ランナーはモデルとツールのアダプターを注入する。通常のテストは台本どおり応答する偽モデルで配線を検証し、実LLM・外部APIは呼ばない。この結果を実モデルの正答率として表示しない。

実モデル実験には、対象モデル、送信先、使用する合成データ、最大試行数、利用枠・総費用上限の確認が別途必要。利用量が返らなければ不明とし、0円とは扱わない。既存の環境変数に資格情報があっても自動利用しない。

プラグインは接続先AIの自由文を強制停止できない。表示まで厳密に制御したい場合は、ホスト側が検証結果を固定形式で表示する別の設計が必要。この実験では、現在のプラグイン利用形態でどれだけ改善し、何が残るかを測る。

## ローカルで準備する

`npm run eval:empirical:prepare` は、12問×2条件の入力を `_build/empirical-v1` に作るだけで、モデルもツールも呼ばない。

- `model-input.json`：両条件で同じ規則・質問・事実・公開回答形式。正解や期待引数は含めない
- `scoring-only.json`：独立した期待値と各ターンの期待結果。モデルや検索インデックスへ渡さない
- `manifest.json`：入力・正解のハッシュ、予定24試行、未実行状態。モデル、精度、費用は未確定

ライブラリの `runEmpiricalExperiment` には利用承認済みのモデルアダプターと実験用ツール実行器を明示的に渡す。現在、実モデルを呼ぶアダプターやChatGPT画面操作は付属しない。台本モデルの動作試験を実LLMの成績として報告しない。

数値等の最終構造化一致に加えて、`turnAnswers` がある場合は各ターンと会話全体の構造化一致を記録する。途中で逸脱し最後に戻った試行も、会話全体では失敗になる。複数ターンの正解が未指定なら会話採点は未実施とする。全文と運用上の意味のレビューは引き続き別途必要。

今回の候補関数は1つだけで、関数検索・多数候補からの選択能力を検証したとは言えない。

## ログイン不要の内部モデル・パイロット

ChatGPT画面での認証を行わない場合、会話履歴を引き継がない独立したAI実行で同じ2条件を試せる。これはChatGPT製品上の挙動・プラグイン接続の評価ではない。両条件は同じ継承モデルと推論設定を要求し、内部の固定モデルリビジョンが取得できない場合は未確認と記録する。

各問題・条件は別の新しい実行にする。追加質問だけは同じ実行へ、初回回答の後に順番に渡す。自然言語条件はツールを使わないよう指示し、プログラム条件は `scripts/native-empirical-call.py` を介して自ら選んだ引数を送る。これは権限レベルで全ツールを遮断した比較ではなく、指定された利用条件での探索的比較である。

記録器は固定Pythonソースのハッシュを確認し、実際の要求・応答・経過時間を `_build/native-empirical-pilot/tool-traces` に残す。各試行は最大6呼び出し。試行用AIへ正解表や他条件の回答を渡さず、途中で正誤のフィードバックや引数補正を行わない。モデルの内部思考は収集せず、ユーザー向け回答と実行証拠だけを記録する。

## 2026-10-02 の予備実験結果

[保存済み実験結果](../experiments/results/2026-10-02-cancellation-v2/README.md)に、全24会話・28回答と固定プログラム実行記録を保存した。自然言語条件とプログラム実行条件はともに12/12会話で構造化回答が一致し、この小規模実験で精度差は確認できなかった。別 AI による文章レビューも明確な逸脱を認めなかったが、人間による判定や一般的な精度保証ではない。モデルを追加で呼ばず、公開した観測データから再採点できる。
