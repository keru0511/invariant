# dot内で完結するローカルMCP検証環境

## 目的と範囲

開発サーバーとローカルD1を起動し、実際のHTTP/MCP経由で判定を繰り返し検証します。
失敗時は期待値・実際の結果・エラーを保存し、修正後に同じケースを再実行できます。

この環境の動作検証はdomainの5ツールとcalculationのdescribe/evaluate/verifyを対象にします。
propose / commitの実サーバー検証は今回のケースには含めません。
LLMの実呼び出しや、自然言語からのルール生成品質を測るものではありません。

## コマンド

前提: リポジトリ指定のNodeとnpm、および `npm ci` 済みの専用checkout。

- `npm run lab:setup`: ローカルD1へマイグレーションと合成データを投入
- `npm run lab:start`: 準備後、127.0.0.1:8787で開発サーバーを起動。Ctrl+Cで終了
- `npm run lab:check`: 準備→空きポートで起動→HTTP/MCP検証→結果保存→サーバー終了を一括実行

`lab:check` が成功なら終了コード0、検証失敗なら1、中断なら130です。
任意URLやリモート実行オプションは受け付けません。同じ作業ディレクトリでの同時起動は拒否します。
異常終了でロックが残った場合は `_build/local-lab/active.lock/pid` のプロセスが停止していることを確認してから、
そのロックディレクトリのみを取り除いてください。稼働中のロックは消さないでください。

## 起動されるもの

- リポジトリに固定されたWranglerのローカルWorker実行環境
- 専用のローカルD1（workspace: `local-lab`、domain: `demo`、`demo-knowledge`、`demo-cas`）
- fixtures/domain-v0の合成データ。バージョンIDはカタログ内容のハッシュから生成
- 本番エントリーポイントを呼ぶ開発専用ラッパー。固有の応答ヘッダーで別サーバーへの誤接続を防止

本番の `wrangler.jsonc`、Worker、認証実装は変更しません。
状態・生成設定・ログはすべてgitignore済みの `_build/local-lab/` 配下に保存します。
同じカタログの再投入は既存バージョンを上書きしません。

## 検証内容

- healthとdomain.pingの疎通
- 保存済みドメインのdescribe / validate / search
- 他のワークスペースを参照できないこと
- manifestに載る8ケース（許可、拒否、不明、矛盾、曖昧、型エラー）の意味上の期待値との一致
- 追加の5反例（公開版の未解決知識・矛盾、入力不足、未登録関数、数値オーバーフロー）を含む合計13ケース
- 上記13ケースを2回実行し、応答全体が一致すること
- 内容アドレス型の旧版/新版の2ケースを追加し、年齢20に対するallow/denyと親版・ハッシュを確認し、反復一致も検証
- 計算の5ケース（小数加算・分数/丸め・割合・ゼロ基準・入力不足）を加えた20ケースに、正確な分数の主張と誤った断定の検出2ケースを追加（合計22ケース）

テストコードによる関数呼び出しだけでなく、起動したWorkerのHTTPルートとローカルD1を通します。
単体テストは `npm test`、実サーバー検証は `npm run lab:check` と分離しています。

## 改善を繰り返す手順

1. `npm run lab:check` を実行
2. `_build/local-lab/latest.json` の失敗ケースと診断を読む
3. 期待値の根拠を確認し、実装を修正。通すためだけに期待値を書き換えない
4. `npm run typecheck`、`npm test`、`npm run lab:check` を再実行
5. 改善と回帰の有無を確認し、レビュー用PRにまとめる

各回のレポートは `_build/local-lab/reports/` に別名で残ります。
`latest.json` には直近の結果、開始・終了時刻、コミットIDと未コミット変更の有無を記録します。
起動・準備段階の失敗も `lab:check` の失敗レポートに残します。
同時実行の拒否は稼働中の検証結果を上書きしません。

これは改善のための検証基盤です。無期限の自動修正、PRの自動マージ、本番反映は行いません。

## 安全上の制約

この環境は**テスト用の認証バイパス**を使用します。

- 待ち受けは127.0.0.1に固定。生成設定のデプロイ、外部公開、トンネル接続は禁止
- dot内のローカルHTTPクライアントから呼ぶための環境です。dotのプラグイン一覧への登録は行いません
- プラグインとして外部から接続する場合は、別途認証付き構成と接続設定が必要
- 子プロセスにはOpenAIやCloudflareの資格情報を引き継がず、外部LLM設定も空に固定
- `.env` / `.dev.vars` があるcheckoutでは起動を拒否。秘密情報のない専用checkoutを使う
- ローカルの合成データだけを扱い、実会話や顧客データは投入しない
- セットアップは `--local`、開発サーバーは `--local --ip 127.0.0.1` を固定。Cloudflareへのデプロイはしない
- 検証終了時に起動したプロセス群を停止。SIGINT / SIGTERMでも後始末する

サーバーは常時稼働を保証するものではありません。検証ごとに起動・終了する運用を標準とします。
