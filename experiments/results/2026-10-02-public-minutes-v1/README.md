# 公開議事録からのタスク抽出：検証・修正の比較

## 結論

今回の小規模な予備実験では、決定的な整合性チェッカーを追加すれば、議事録から起こすタスクの意味的精度が安定して上がる、とは確認できなかった。

固定参照への一対一対応では、プログラム補助側の属性不支持は少なく、参照候補の回収は1件少なかった。ただし担当・状態の差の一部は、候補を分割した結果、対応する参照が変わる影響を含む。修正が意味誤りを防いだという因果的な差とは認定しない。両条件とも、過去の実施年度・着手時期を確定納期として扱う同じ2件の誤りを残した。これは今回のチェッカーで防げなかった具体例であり、あらゆるプログラム化の無効性を意味しない。

## 資料と実験

- デジタル庁の[2025年5月23日・第2回](https://www.digital.go.jp/policies/assessment/2025-2nd-session)と[2025年8月4日・第4回](https://www.digital.go.jp/policies/assessment/2025-4th-session)の公開議事概要
- 提案、実施計画、既完了の具体的行為を含む連続6区間を、モデル出力を見る前に選択。ランダム標本ではない
- 各区間で実モデル初稿を1回生成し、同じ初稿を2条件へ分けた
- A：同じ原文・規則・スキーマで自己点検し、1回修正
- B：Aと同じ入力に、固定プログラムによる初稿の診断結果を加え、1回修正
- 18回の推論を実施し、6初稿と10修正の計16抽出を保存。JP01の両修正は入力配送の切り詰めで失敗。再試行せず、予定数に残し、精度比較と分離した
- 有効な対応比較はJP02〜JP06の5区間。初稿の集計も同じ5区間にそろえた
- 同じ継承モデルを指定したが、正確なバックエンド版、温度、seed、トークン数、費用は取得できない。ChatGPTアプリでの評価ではない

これは、ゼロからの抽出全体や関数検索の比較ではなく、固定初稿への検証・修正の効果を調べる実験である。

## 結果

独立したAI参照をモデル出力未閲覧で作成し、別AIの原文レビューで改訂・固定した。採点は条件名を隠した別AIが実施した。人による正解確認ではない。

| 項目 | 初稿 | A 自己点検 | B プログラム補助 |
| --- | ---: | ---: | ---: |
| 全状態の参照候補34件の検出 | 32 | 33 | 32 |
| 出力候補数 | 44 | 49 | 48 |
| 対応できた候補の状態不支持 | 1 | 2 | 1 |
| 対応できた候補の担当属性不支持 | 0 | 1 | 0 |
| 対応できた候補の時期属性不支持 | 2 | 2 | 2 |
| 対応できた候補の根拠の意味関係不支持 | 3 | 3 | 2 |

属性不支持は固定参照に対応できた候補だけの件数で、出力全体の誤り率ではない。対応先変更による増減を、実際の意味誤りの増減と混同しない。項目間に重複があり、合算しない。時期不支持の2件は対応済み参照単位の数で、Aには未対応の重複候補にも同じ時期属性が残る。参照に対応しない候補には、原文に支持される細分化や参照側の見落としもあるため、すべてを捏造とは扱わない。

実行対象（committed）の固定参照照合では、Aのprecisionは73.7%、recallは87.5〜100%、F1は80.0〜84.8%。Bはそれぞれ73.7〜78.9%、93.3〜100%、82.4〜88.2%。同じ参照解釈を両条件に適用したF1差は0〜5.9ポイントで、改善ゼロの解釈も残る。BのF1範囲は初稿と同じである。実行確定が一意の参照だけを採用する解釈では、3条件ともF1は84.85%で一致する。

この範囲は曖昧な発言に対して先に定めた許容状態の組合せによるもので、統計的信頼区間ではない。開発全体・UI/UX・中核機能を一つの階層にまとめる事前規定の感度分析でも、改善ゼロの解釈が残った。詳しい件数と範囲は[summary.json](summary.json)に保存した。

## チェッカーが保証したもの・しなかったもの

16抽出はすべて機械チェックを通過した。引用の存在、JSONの型、モデルが宣言したイベントと最終状態の整合などは検査できたが、そのイベントが本当に原文の意味を表しているかは認定していない。

今回、過去・開始の時期を確定納期とする誤りは初稿から両修正へ残った。また、一つの提言に対する応答を別の提言の受諾・担当引受けまで広げる対応付けも、形式が整っていれば通り得る。プログラムが照合する元の事実や意味ラベルをLLMが誤って作れば、内部整合だけで止められない。

一方で、今回の主観的な参照にも担当者や提案の見落としの懸念が残った。出力を見て参照を都合よく修正せず、そのまま留保として記録している。小さな数値差を実用上の精度向上と断言できる段階ではない。

## 再現できる範囲

[最小キット](../../public-minutes-v1/README.md)に固定規則・スキーマ・チェッカー・架空例の11機構テスト・公式ページから同じ本文を取得するスクリプト・ハッシュを収録した。11テストはモデル精度ではない。

元の議事録と長い原文引用を含む回答・採点資料は、第三者の権利に関する留保を考慮し再公開しない。したがって公開キットだけで今回の意味採点を完全に再採点できるわけではない。ローカルでは入力・回答・診断・固定参照と匿名採点を保存した。公開内容で再現できるのはコーパス取得と機械検査であり、新しいモデル実験は別の実行になる。

明示的な撤回例は含まれず、撤回処理の頑健性は未検証。モデル入力の隔離は指示によるもので、ツールの物理的無効化ではない。入力ファイルの分割読取は配送失敗後に全残り条件へ同じように許可し、終了済み失敗試行は再実行していない。

## 次に優先すること

機能数を増やす前に、タスク候補と原文の意味的対応を検査する層、時期の種類（開始・完了実績・目標・期限）の区別、合意が不明な候補を確定タスクへ昇格させない運用を検証する価値がある。ただし意味判定を別のLLMに任せるだけでは保証にならず、担当者による確認と明示的な承認状態が必要になる場面は残る。
