# 公開議事録抽出パイロット：最小再現キット

公開議事録からの構造化抽出について、固定した初稿への自己レビューと、決定的チェッカーを併用したレビューを比較するための方法・実装です。精度改善を示す結果ではありません。

## 同梱物

- `checker.py`：原文引用・型・状態などの機械的整合性チェック
- `test_checker.py`：手書きの架空例による11件の機構テスト
- `public-rules.json` / `public-schema.json`：固定規則と出力スキーマ
- `sources.json`：公式出典、取得日時、会議日、選択位置、SHA-256、利用条件へのリンクのみ
- `fetch_cases.py`：公式の2ページを取得し、同じ6区間を抽出するスクリプト
- `SHA256SUMS`：配布ファイルのSHA-256

先頭4ファイルは実験時の固定版からバイト単位で変更せず収録しています。実際のモデル回答、内部の実行指示、採点用正解、評価レビュー、元の議事録本文は同梱していません。テスト内の短い例文は機構確認用に作成された架空例です。

## ローカルでの再現

Python 3.9以上を使用します。チェッカーと11件のテストは標準ライブラリのみです。公式ページの取得・HTML抽出には別途 `lxml` が必要です。このキットは依存ライブラリを自動インストールしません。

```sh
sha256sum -c SHA256SUMS
python -m unittest -v test_checker.py
python fetch_cases.py --output-dir ./local-corpus
```

`fetch_cases.py` は明示的に実行されたときだけネットワークへ接続します。`--help` やモジュールの読み込みでは取得しません。`sources.json` を同じフォルダーに置き、既存でない出力先を指定してください。

HTMLの `br` を改行に変換し、最初の `article` 内の見出し・段落・リスト項目を原文順で抽出します。親 `li` を持つ要素は重複防止のため除きます。位置は0始まりで、ブロックの終端は包含、行の終端は非包含です。選択区間は次の通りです。

- JP01：第2回、ブロック24、行0〜19
- JP02：第2回、ブロック26、行0〜23
- JP03：第2回、ブロック26、行24〜35
- JP04：第4回、ブロック58〜64
- JP05：第4回、ブロック66〜69
- JP06：第4回、ブロック73〜80

取得した6区間の本文SHA-256が実験時の値とすべて一致した後だけ `cases.json` を保存します。不一致なら失敗し、新しい内容を同じコーパスとして扱いません。HTML全体だけが変わり、本文6区間は同じ場合は警告して続行します。取得時点のHTMLハッシュは `fetch-manifest.json` に、実験時のHTMLハッシュは `sources.json` と各ケースの `source_raw_html_sha256` に記録します。

生成ケースには原文の本文、段落ID、メタデータが入ります。元データの周辺文脈フィールドは再生成しません。証拠として使えるのはケース内の `paragraphs` だけです。本文全体の再配布を避けるためHTML・全文テキストは保存しません。生成した抜粋とモデルの引用を含む出力もローカルで管理してください。

チェッカー入力は `case` と `extraction` の2キーを持つJSONです。`case` に取得した1ケース、`extraction` に規則とスキーマに従ったモデル出力を置きます。

```sh
python checker.py < input.json > diagnostics.json
```

機械的エラーがなければ終了コード0、あれば1です。`semantic_guarantee` は常に `false` です。チェッカー合格は意味の正しさ、漏れのなさ、モデル精度を保証しません。

## 比較設計と現在の制約

計画は6ブロック・18呼び出しです。各ブロックについて初稿を1回生成し、その同一の初稿を固定して次の2条件へ分けます。

1. A：原文・規則・スキーマ・固定初稿を受け取り、自己レビューで1回だけ修正
2. B：Aと同じ入力に初稿のチェッカー診断を追加し、1回だけ修正

つまり各ブロックは「初稿1回＋A1回＋B1回」の3呼び出しです。Bも修正を繰り返しません。比較時には同一の初稿・原文・規則・スキーマを維持し、入力が両条件へ実際に届いたことを確認する必要があります。内部のプロンプトや実行基盤は同梱していないため、このキットはモデル呼び出しそのものを完全再演するものではありません。

実際のパイロットではJP01のA/B両条件に入力配送の失敗があり、JP01を有効な対応比較に数えることはできません。実施した比較はJP02〜JP06の5有効ペアです。[結果と留保](../results/2026-10-02-public-minutes-v1/README.md)を参照してください。モデルのバックエンドとトークン費用は不明です。このキットにはモデル精度の主張、A/Bの優劣、精度改善率は含めません。11件のテスト通過はチェッカーの機構確認であり、モデル精度の検証ではありません。

## 出典と権利

公式出典はデジタル庁の2025年度第2回・第4回の議事録ページです。正確なURL、取得日時、利用条件と著作権ポリシーへのリンクは `sources.json` にあります。抽出データはデジタル庁の公開ページを加工したものです。

公開されている資料でも、すべての内容が無条件で再配布可能とは限りません。第三者の権利や個別に示された条件が適用される可能性があります。利用者自身が公式ページと現在の利用条件を確認し、公式ページから取得してください。この配布物では全文議事録、長い原文引用を含む回答、採点用資料を再公開しません。取得した本文・長い引用を含む出力はローカルに留め、別途公開する場合は必要な権利確認と出典表示を行ってください。
